# Handoff 템플릿 (새 폴더 세팅용)

## 0. 파일 역할 — 조회 키가 다르다

날짜별 기록만 쌓으면 나중에 못 찾는다. 아무도 *"7월 22일에 뭐 했지?"* 로 검색하지
않는다. **"θ 피복률 왜 그렇게 정했지?"** 로 찾는다. 그래서 **사안별 파일**과
**시간축 파일**을 나눈다.

| 파일 | 조회 키 | 갱신 | 다음 세션이 읽나 | 수명 |
|---|---|---|---|---|
| `STATUS.md` | — (현재) | 매 세션 **덮어쓰기** | **항상** | 현재만 |
| `dead-ends.md` | 사안 | 실패할 때마다 append | **항상** | **영구** |
| `decisions/NNNN-*.md` | 사안 | 결정할 때마다 새 파일 | **인덱스만** → 필요한 것만 열기 | **영구** |
| `LOG.md` | 시간 | 매 세션 append | 최신 1개만 | 요약 후 아카이브 |
| `CLAUDE.md` | — | 드묾 | 자동 로드 | — |

**확장성 기준은 하나뿐**: *다음 세션이 읽는 양이 시간에 따라 늘면 안 된다.*
`STATUS`는 1페이지 고정, `decisions/`는 인덱스만, `LOG`는 최신 1개만 읽는다.

`SessionStart` 훅이 설치돼 있으면 `STATUS.md` · `dead-ends.md` · `decisions/` 인덱스 ·
`LOG.md` 최신 엔트리가 **새 창을 열 때 자동 주입**된다. "이어서"를 치지 않아도 된다.

---

## 1. CLAUDE.md 상단 연속성 헤더 블록 (복붙)

```markdown
> **세션 연속성 (handoff 스킬)**:
> - **시작 시**: `STATUS.md` + `dead-ends.md` + `decisions/` 인덱스 + `LOG.md` 최신 1개.
>   (SessionStart 훅이 있으면 자동 주입되므로 다시 읽지 말 것.) → "여기까지, 다음 X" 요약부터.
> - **끝낼 때** ("저장"/"오늘 정리"): `LOG.md` append + `STATUS.md` 덮어쓰기.
>   확정된 결정은 `decisions/`로, 실패는 `dead-ends.md`로 **승격**시킨다.
> - **월간** ("월간 정리"): LOG 아카이브. 막다른 길·판정·결정은 **버리지 않는다**.
> ⚠️ `find`/`du` 트리 전체 스캔 금지(페이지캐시 렉).
```

## 2. STATUS.md (1페이지 고정, 매 세션 덮어쓰기)

```markdown
# STATUS — YYYY-MM-DD

## 지금 어디 (한 줄)
<프로젝트가 지금 어느 지점인지 한 문장>

## 진행 중 (도는 잡 + 대기 결과)
| Job | 뭐 | 상태 | 완료 시 판정 |
|---|---|---|---|
| <id> | <설명> | RUNNING/PENDING | <무엇을 보고 판단> |

## 즉시 다음 수 (우선순위)
1. <가장 먼저 할 것 — 구체적으로>
2. <그다음>

## 열린 질문 (아직 모르는 것)
- <질문> — 답하려면 <무엇이 필요한지>

## 최근 산출물 (파일 경로)
- <path> — <뭐>
```

## 3. LOG.md 엔트리 (append-only) — **"한 것" 나열 금지**

어제의 claude가 가졌던 것 중 파일에서 복구되는 건 **사실뿐**이다. 판단·합의·무지의
경계는 적지 않으면 사라진다. 그래서 LOG는 그 셋만 적는다.
*"데이터셋 9개 받고 리포트 만들었음"* 은 **적지 마라** — 폴더가 이미 말한다.

```markdown
## YYYY-MM-DD (한 줄 요약)

### 판정 — 오늘 확정된 것
- <주장> — 근거 <파일:키 또는 DOI> — [계산확인|문헌확인|추정]

### 결정 — 왜 그렇게 했나
- <선택> ← <버린 대안>과 그 이유  → decisions/NNNN-<slug>.md

### 막다른 길 — 반복 방지
- <시도> → <실패 이유>  → dead-ends.md 에도 한 줄 추가

### 열린 질문
- <아직 모르는 것> — 답하려면 <무엇이 필요>

### 다음 수
1. <구체적으로>
```

`결정`과 `막다른 길`은 **본문을 여기 묻지 말고 전용 파일로 승격**시키고 여기엔
포인터만 남긴다. LOG는 시간축 색인이지 저장소가 아니다.

## 4. dead-ends.md (영구 · 매 세션 자동 주입 · 절대 삭제 금지)

가장 값어치 있는 파일이다. 같은 실패를 두 번 하지 않게 해준다.

```markdown
# 막다른 길 — 이미 실패한 것. 다시 시도 금지

## 코드 · 파싱
- `energy_of()` 가 `title="freeEnergy"` 검색 → 실제 태그는 `dictRef="cc:freeEnergy"`(배열).
  에너지가 전부 None 이 됨. 배열 마지막 값을 취할 것. (2026-07-28)

## 계산 세팅
- <세팅> → <수렴 실패 / 잘못된 결과> + 왜. (YYYY-MM-DD)

## 환경 · 도구
- <시도> → <실패> + 왜. (YYYY-MM-DD)
```

---

## 5. decisions/NNNN-<slug>.md (ADR 방식 · 영구)

**결정 1건 = 파일 1개.** 날짜가 아니라 사안이 단위다. 나중에 *"왜 그렇게 했지?"* 로
찾을 수 있는 유일한 형태다.

```markdown
# NNNN. <결정을 한 문장으로>

- 상태: 채택 | 대체됨(→ NNNN) | 폐기
- 날짜: YYYY-MM-DD

## 맥락
<무엇을 정해야 했나. 어떤 제약이 있었나.>

## 결정
<무엇으로 정했나.>

## 버린 대안
- <대안> — 버린 이유

## 결과
<이 결정 때문에 앞으로 무엇이 강제되나 / 무엇이 불가능해지나.>

## 근거
- <파일:키 / DOI / 계산 결과> — [계산확인|문헌확인|추정]
```

번호는 001부터 순번. 뒤집힐 때 **파일을 지우지 말고** 상태를 `대체됨(→ NNNN)` 으로
바꾸고 새 파일을 쓴다. 뒤집힌 이유 자체가 기록이다.

---

## 6. 월간 아카이브 규칙 — 칸마다 수명이 다르다

| 칸 | 오래되면 |
|---|---|
| 막다른 길 | **영구 보존.** 버리면 같은 실패를 다시 한다 |
| 판정 | 영구. 뒤집히면 지우지 말고 취소선 + 정정 링크 |
| 결정 | 영구 (`decisions/` 에 이미 분리돼 있음) |
| 열린 질문 | 닫히면 판정으로 이동 |
| 다음 수 · 진행 중 잡 | **하루살이. 아카이브 때 버려도 됨** |

"한 달 지나면 폐기"는 하지 마라 — 막다른 길을 버리는 순간 같은 실패를 반복한다.
